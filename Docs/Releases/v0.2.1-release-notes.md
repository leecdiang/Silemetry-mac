## 稳定性与数据完整性修复

### 🔧 Telemetry 句柄生命周期与并发安全

所有 Rust-handle FFI 调用（create/start/wait/stop/destroy）统一在一条串行队列上执行；stop 排在 in-flight read 之后，确保 `wait_next` 返回后才会 `destroy`——消除并发别名与 use-after-free。Actor 不再直接触碰裸指针（错误详情在队列内捕获）。`TBTelemetryHandle` 以 `@unchecked Sendable` 包装，把安全不变式交给类型系统检查。

### 🎯 逐指标有效性掩码（per-metric validity masks）

Rust `available_mask` 改为逐指标判定：温度要求传感器计数 + is_finite + 合理范围，功率要求有限且 ≥0，频率要求 >0，利用率限定 0..1。不再有"一刀切"的 blanket valid。Rust 序列号从 1 开始，首条采样不再被跳过。

### 🛑 Stop / Discard / 失败终结路径

- 保存失败后的 Discard 会显式从 ModelContext 删除记录——不再有指向已删 JSONL 的孤儿记录
- `.failed` 状态与归档写入错误在 UI 中可见
- Monitor Only 的失败计数改为连续失败计数，起始与成功读取时重置

### 📦 JSONL 归档完整性与流式摘要

- `ArchiveLoadResult` 用磁盘上的实际文件（行数 / 畸形行 / 存在性）交叉校验存储的摘要；归档缺失、截断或损坏时，存储的 `Complete` 运行时降级为 `Partial`（Results + Compare 均生效）
- JSONL 解码按行流式处理（64 KB 分块），长时运行下 Compare 峰值内存显著下降

### ⚖️ Compare 可比性与损坏数据检查

- 结论使用磁盘生效的 raw 状态，顶部结论、详情表与曲线横幅永远不可能互相矛盾
- 可比性规则收紧：环境温度差 >2 °C、双方条件均未知、双方均为旧版关键元数据时，不再当作"高度可比"，改为告警

### 🔄 SwiftData 回滚与文件事务

- SwiftData 写入失败立即回滚（Retry 重新插入；Discard 仅删文件）
- History 删除 / 重命名回滚时文件恢复、旧名保留；样本目录先暂存到 Trash，仅在记录删除保存成功后清除，失败则恢复并报错
- 重命名不再吞掉保存错误

### 💻 动态设备、电源变化与真实 startedAt

- `RunRecord` 记录测试开始/结束时的电源来源与 Low Power Mode，带变化标志；Compare 对测试中途 AC↔电池或低功耗切换给出告警
- `createdAt` 反映真实测试开始时间，而非终结时间
- 电池不可读的 run 保持 Unknown，不再误标为 Battery
- `saveInterrupted` 从流式累加器（而非 7200 样本的 UI 环形缓冲）终结数据
- Compare 在后台线程加载样本文件，带进度反馈

### ✅ 测试与 CI

- 70/70 单元测试通过；CI #15 success（Xcode 15.4 / macOS 14 运行时）
- 测试套件整体 `@MainActor` 化，消除 SwiftData 模型的 Sendable 越界警告；独立测试二进制嵌入 Info.plist 与内存 ModelContainer，兼容 macOS 14 运行时
